# AI 应用开发学习手册（RAG → Agent → 工程化 → 求职西安）

> 写给：民办本科大四、会 Python/FastAPI/MySQL/Vue3 基础、正在做 AI 取名助手、目标西安 AI 应用开发实习的你。
> 全文大白话，不堆术语，每句都能落地。字数约 7500。

## 一、AI 应用开发知识体系思维导图

### 1. 大模型基础
- LLM（大语言模型）：会"预测下一个字"的超级文字生成器，你说一句它接一句
- Token：AI 认字的单位，1 个汉字约 1~2 个 Token，API 按它计费
- 上下文窗口：AI 一次对话最多记住多少字，超了前面的内容就"忘"
- Prompt 工程：用合适的话让 AI 输出你要的东西，核心四要素=角色+任务+格式+例子
- 结构化输出：强制 AI 返回固定格式（如 JSON），程序才好处理（你的 Pydantic Schema 就是干这个）
- Temperature：AI 的"随机性"旋钮，0~1；取名要多样性调高，要稳定答案调低

### 2. RAG（检索增强生成）
- 解决什么：AI 会一本正经地胡说八道（幻觉），知识停留在训练时（过时）
- Embedding：把文字变成一串数字（向量），意思越近数字越像
- 向量数据库：专门存数字串并快速找最相似的；MySQL 做不了语义搜索
- Chunk 切分：长文档切成小块再存，检索才精准
- 相似度搜索：拿问题向量找最近的 K 个（余弦相似度；ANN=偷懒但快的近似算法）
- 完整流程：离线建库（提前向量化存好）+ 在线检索（用户来时秒查）
- 进阶：混合检索（关键词+向量）、Rerank 重排、评测集评估

### 3. Agent（智能体）
- 和普通调 API 的区别：普通是一问一答；Agent 能自己决定调什么工具、多步完成任务
- Tool Calling：给 AI 一份"工具清单"，它需要时自己调用（查天气、查数据库）
- ReAct 模式：AI 循环"想→做→看"，直到解决问题
- 多 Agent 协作：多个 AI 分工，如一个出方案、一个审查
- 框架对比：LangChain（生态最全、上手快）、LangGraph（图编排、适合复杂流程）、CrewAI（多角色简单）

### 4. AI 应用工程化
- 流式输出（SSE/WebSocket）：AI 一个字一个字"打字"，用户体验好
- Token 成本控制：精简 Prompt、缓存重复问题、简单问题用小模型
- 错误处理和重试：超时/限流要重试（指数退避），给用户友好提示
- 日志和监控：记录每次请求的耗时、Token、命中情况（LangSmith 等）
- 缓存策略：相同问题直接返回缓存（Redis）
- 安全：防 Prompt 注入（用户输入里夹带"忽略之前的指令"）

### 5. 技术栈（各是干嘛的）
- FastAPI：写接口，你的后端
- SQLAlchemy + Pydantic：操作 MySQL + 数据校验（你已会）
- MySQL：用户、历史记录等结构化数据
- Redis：缓存、限流
- Milvus / Chroma / pgvector：向量数据库（Chroma 轻量适合学习，Milvus 生产级）
- LangChain：AI 应用框架（链、Agent、记忆）
- DeepSeek / OpenAI API：大模型本身
- Vue3 / React：前端展示，要学会接流式输出
- Docker + Nginx：打包部署、反向代理

## 二、RAG 核心概念大白话（图书馆比喻）

> 把 AI 想成一个"只背过教材、容易编答案的图书管理员"。RAG 就是给他配一个真正的图书馆，让他照着书答。

- **Embedding = 给每段文字做"内容指纹"**：把文字变成几百个数字，意思越近数字越像。"海上生明月"和"思念故乡"的指纹很接近。→ 取名项目里：诗词和用户需求都要转成向量。
- **向量数据库 = 按"意思相近"排书的图书馆**：MySQL 只能按标题/关键词找书（LIKE），向量库能按意思找。→ Milvus 存 1万+ 首诗词向量。
- **Chunk 切分 = 把厚书拆成单页卡片**：整本书向量化会糊成一团，拆成小段才好检索。→ 一首诗/词就是一块（天然适合）。
- **相似度搜索 = 管理员按指纹找最像的卡片**：拿用户问题的指纹，找最近的 K 张。→ milvus_search_demo.py 干的事。
- **离线建库 vs 在线检索 = 提前抄好索引卡 vs 用户来了秒查**：1万+ 首转向量要几十分钟，不能等用户；用户一个问题转向量只要零点几秒。→ import_poetry_vectors.py（离线）和取名接口（在线）。
- **为什么拼进 Prompt = 把原文拍在 AI 面前，逼它照着念**：不拼原文只能靠记忆编；拼进去后 AI 看着材料答，出处可查、幻觉大减。→ agent.py 里把检索到的诗注入提示词。
- **RAG 和 Agent 的关系 = RAG 给 AI"知识"，Agent 给 AI"手脚"**：RAG 解决"不知道"，Agent 解决"不会干活"；可组合：Agent 决定要什么资料→RAG 检索→再回答。

## 三、可执行学习路径（共 6~9 周，每天 2~3 小时）

### 阶段 1：RAG 基础（1~2 周）
- 目标：能独立做一个"文档问答"小系统
- 知识点：Embedding、Chunk、向量库（先 Chroma）、检索、拼 Prompt
- 免费资源（真实存在）：① DataWhale 开源教程《llm-universe》（GitHub 搜 datawhalechina/llm-universe，中文，从 Prompt 到 RAG 到 Agent 都有）② 吴恩达《ChatGPT Prompt Engineering for Developers》（B站搜中文版）③ Milvus 官方中文文档（milvus.io/docs/zh，看"快速开始"）
- 练习：Streamlit + LangChain + Chroma 做"本地文件问答"：上传 3 份 PDF/TXT→切片→向量化→问答，答案必须带出处
- 检验标准：换 5 份没见过的文档都能答对细节问题；能说出"为什么答案必须带出处"
- 预计时间：1~2 周

### 阶段 2：Agent 基础（1~2 周）
- 目标：能让 AI 自己调用工具完成任务
- 知识点：Tool Calling、ReAct、LangGraph 入门
- 免费资源：LangChain 官方文档 Agents 章节（python.langchain.com，有中文）、llm-universe 的 Agent 章节
- 练习：做一个"助手"：给 AI 两个工具（查 MySQL 用户数、算两数相加），问它"数据库有多少用户，帮我算两倍"，它要能自己调两次工具
- 检验标准：AI 能自主选对工具、失败自动重试；你能讲出它每一步在干嘛
- 预计时间：1~2 周

### 阶段 3：工程化（2 周）
- 目标：把项目部署上线，处理流式、错误
- 知识点：Docker、SSE、重试、Nginx、日志
- 免费资源：B站"狂神说Docker"（经典中文入门）、FastAPI 官方中文文档、菜鸟教程 Nginx
- 练习：把取名项目做成 docker-compose（后端+MySQL+Milvus）；后端加 SSE 流式接口，前端打字机效果；部署到免费云（阿里云/腾讯云学生试用或低价轻量服务器）
- 检验标准：手机 4G 能打开网址正常取名；把 Milvus 停掉页面有友好提示不白屏
- 预计时间：2 周

### 阶段 4：项目深化（2~3 周）
- 目标：给取名项目加"优化+评估"，能讲出改进数据
- 知识点：混合检索、Rerank、评测集、LangSmith 日志
- 练习：① 做 20 个取名测试用例（如"姓王、女、两字、寓意温柔"）② 人工打分（名字质量/出处相关度）③ 加 Rerank 或调 Top-K、换模型 ④ 对比前后分数写进 README
- 检验标准：能拿出"改进前 65 分 → 改进后 82 分"的具体数据和原因
- 预计时间：2~3 周

## 四、职业发展路径（2026 行情，以实际 offer 为准）

### 初级（0~1 年）
- 必须会（能干活）：Python 写接口、调通大模型 API、做一个 RAG 系统、Docker 把项目跑起来、看得懂报错
- 简历项目：1 个完整 RAG 项目（取名助手）+ 1 个练手项目（文档问答）
- 面试常问：RAG 完整流程？为什么用向量库不用 MySQL？Top-K 是什么？AI 返回格式乱怎么办？FastAPI 依赖注入？索引为什么快？进程/线程/协程区别？
- 薪资：西安实习 150~250/天；初级 6~10k/月；一线城市 10~15k
- 升职信号：能独立接需求→写完→上线，不用人盯

### 中级（1~3 年）
- 必须会：独立设计 RAG/Agent 方案、做评估优化、控 Token 成本、带新人
- 简历项目：2~3 个上线项目 + 1 个有优化数据的项目
- 面试常问：怎么评估 RAG 好坏？检索质量差怎么排查？Agent 多步失败怎么办？怎么降成本？并发和限流怎么做？
- 薪资：西安 12~20k；一线 20~35k
- 升职信号：团队里 AI 相关的事都先问你

### 高级（3~5 年）
- 必须会：架构设计、技术选型、性能优化、跨团队协作
- 简历项目：主导过 1 个从 0 到 1 的 AI 产品
- 面试常问：AI 产品从 0 到 1 怎么设计？数据隐私和合规？模型选型方法论？怎么选 RAG/微调/Agent？如何设计可评测的 AI 系统？大模型应用安全怎么落地？
- 薪资：西安 18~30k；一线 35~60k
- 跳槽信号：现公司没有更大挑战、涨薪停滞

### 专家/架构师（5 年+）
- 必须会：能设计公司级 AI 技术方案、技术选型能影响业务、能带团队/跨团队推进项目
- 简历项目：主导过多个 AI 产品落地，或搭建过 AI 平台/中台
- 面试常问：AI 平台/中台怎么设计？LLMOps 体系怎么搭？如何评估团队技术方案？技术债怎么还？业务诉求和技术方案冲突怎么决策？
- 判断标准：能影响公司技术方向、被邀请做跨部门方案评审
- 方向：AI 应用架构师（系统设计）、LLMOps（平台与工程化）、垂直行业专家（医疗/教育 AI）、技术管理（带团队）

## 五、求职准备清单（西安中小公司）

### 1. 简历怎么写
- 公式：动词 + 做了什么 + 技术栈 + 量化结果。别写"负责后端开发"，写"用 FastAPI 开发取名接口，对接 DeepSeek 实现结构化输出"
- 项目描述范例（可直接改）：
  "AI 取名助手（个人项目）｜FastAPI + Vue3 + DeepSeek + LangChain + Milvus
  ① 实现用户注册登录、JWT 鉴权、取名历史记录；
  ② 构建 RAG 流程：1万+ 首诗词离线向量化入库 Milvus，在线检索 Top5 注入 Prompt，AI 生成 5 个候选名+出处寓意，结构化 JSON 返回；
  ③ 用 docker-compose 部署（后端+MySQL+Milvus），接口 3 秒内返回。"

### 2. 作品集准备
- GitHub 仓库必须有：README（简介/架构图/技术栈/截图/运行步骤/在线地址/优化数据）、代码整洁、有连续 commit
- 必须部署上线（有网址才算作品），再录 3~5 分钟演示视频（B站/网盘）

### 3. 面试准备
- 技术必背：Python（列表推导、装饰器、GIL、async/await）、FastAPI（依赖注入、生命周期）、MySQL（索引、事务、慢查询）、RAG（概念+流程+为什么+怎么优化）、LangChain（Chain/Agent/记忆）
- 项目讲解用 STAR：情境（取名靠 AI 瞎编不可信）→任务（做 RAG 取名）→行动（离线向量化+在线检索+Prompt 注入）→结果（3 秒返回、出处可查）

  数组/哈希（14）：1、242、49、217、169、350、26、88、283、53、121、15、3、11
  链表（8）：206、21、141、160、83、876、19、234
  栈/队列（5）：20、232、155、225、1047
  树（10）：104、226、101、102、98、700、235、110、257、112

  动态规划入门（6）：70、746、198、322、300、5

## 六、常见误区 10 个（为什么是坑、怎么避免）

1. 只看视频不写代码：看 10 小时不如写 1 小时；视频和练习按 1:2 配比，看完当天必须复现
2. 追求新技术忽略基础：面试 70% 是 Python/MySQL/HTTP 基础；新技术是加分项不是地基
3. 项目只跑通不理解：每个函数能用自己的话讲出来才算会（检验法：讲给 AI 听，看它能不能听懂）
4. 简历造假：面试官深挖三句就露馅；宁可项目小，也要真实
5. 憋大招一次性提交：GitHub 每天小 commit，面试官看得到你的过程
6. 不会搜索就提问：先 Google/掘金/官方文档 15 分钟，再带"我试过什么"去问
7. 忽略部署：跑通≠能用；没有上线网址的项目在简历上减分
8. 只背八股不懂原理：面试官爱追问"为什么"，平时多问自己为什么
9. 收藏夹吃灰：每阶段只留 1 个主线资源+1 个练习，学完再开新的
10. 不看招聘 JD：JD 写什么就补什么，用 JD 倒推学习优先级
