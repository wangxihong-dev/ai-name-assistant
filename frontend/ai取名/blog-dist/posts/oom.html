2 核 4G 的机器上 Milvus 被 OOM 杀掉，我是怎么查到的 ​

2026-09

第一次挂的时候，我以为我修好了 ​

我服务器是阿里云 2 核 4G，上面跑六个容器，MySQL、etcd、MinIO、Milvus、后端、前端。平时 docker stats 一看基线占用就 2.1G 左右，Milvus 最大，八九百兆。

内存一直挺紧的，但能跑。

然后有一天网站打不开了。free -h 一看内存快满了。我当时的判断特别快，内存不够，加 Swap。

加了 Swap，重启，网站活了。我就以为这事完了。

9 月 2 号它又挂了 ​

这次现象更怪。

free -h 显示内存只剩 94M，而我加的 Swap 有 8G，用量是 0。

一整块备胎挂在那儿，一点没动。

系统已经半瘫了，docker ps 敲下去卡住不返回。我重启了 ECS，六个容器靠 restart: unless-stopped 自己拉起来了，网站恢复。

但这次我没敢直接收工，因为"加了 Swap 却没用上"这件事说不通。

四条证据 ​

一，free -h。内存将满，Swap 用量 0。备胎存在但没被用，这不是 Swap 不够，是根本没打算用 Swap。

二，cat /proc/sys/vm/swappiness

0

看到这个数字我愣了一下。swappiness 是 0 到 100 的一个开关，表示内核愿不愿意用 Swap。0 的意思就是宁可杀进程也绝不动 Swap。

三，journalctl -k -b -1 | grep -i -E "oom|kill"

-b -1 是上一次启动的日志，因为 OOM 发生在我重启之前。日志里实锤了，OOM killer 杀掉了 milvus，当时它占 1.68G。

四，docker ps 佐证。Milvus 显示 Up 8 分钟，其他容器 Up 10 分钟。

差的那两分钟就是它被杀掉之后自动重启的时间。这条不是必需的，但它跟第三条对上了，我就知道没查错。

为什么阿里云要设成 0 ​

查完我特意去看了下，是 /etc/sysctl.d/99-apsara-sysctl.conf 里写的，阿里云自己塞的默认配置。

想明白之后觉得也合理。云厂商假设你要极致性能，宁可杀进程也不让你卡。Swap 是拿磁盘当内存，一旦用上延迟会很难看。对大厂那种机器这个取舍是对的。

但我这是 2 核 4G 跑六个容器的玩具机。我要的不是极致性能，是别死。

所以小机器上这个参数得自己改回来。60 是 Ubuntu 的默认值。

改的时候有个小讲究 ​

bash
sysctl -w vm.swappiness=60        # 立即生效

然后写进 /etc/sysctl.conf 让它重启后还在。

我一开始想去直接改 /etc/sysctl.d/99-apsara-sysctl.conf，后来没动。两个原因，那是厂商自动写的，系统更新可能给我重置回去。再一个 /etc/sysctl.conf 的优先级更高，能稳稳盖住它。

改完再 free -h，Swap 有用量了。这次我看到 Swap 被用反而是好事，说明备胎真的开始工作了。

我学到的其实不是 swappiness ​

是这个。

第一次我加了 Swap，网站好了，我就以为修好了。我从头到尾没验证过 Swap 到底有没有被用上。

如果我当时多敲一句 free -h 看一眼 Swap 用量，就会发现它一直是 0，问题当天就能定位。

这跟我写代码那个毛病是一模一样的。我写过 try/except 就以为异常被处理了，写过 logger.error("超时") 就以为超时被兜住了，设过 tool_choice='required' 就以为强制生效了。写了不等于生效，加了不等于用上。

后来我给自己定了条规矩，改完一个东西，验收标准必须是"我去把结果查出来、眼睛看见了"，不是"它没报错"。

这条规矩后来救过我好几次。比如有一次导入脚本退出码是 0，我以为插进去了，去库里一查，0 行。

一些我到现在也没完全搞明白的 ​

journalctl -k 和 dmesg 的区别我讲不清楚，我只知道 -k 是只看内核日志、-b -1 是上一次启动。

OOM killer 挑进程杀的规则，我知道是看内存占用，所以每次死的都是 Milvus。但那个 oom_score 具体怎么算的我没研究。

还有 Swap 用多了会不会拖慢 Milvus 的查询，我没测过。现在的状态是偶尔用一点，我觉得能接受，但这是感觉不是数据。

命令备忘，下次再挂直接用：

bash
free -h                                         # 内存和 Swap 各用了多少
cat /proc/sys/vm/swappiness                     # 内核愿不愿意用 Swap
journalctl -k -b -1 | grep -i -E "oom|kill"     # 上一次启动里谁被杀了
docker stats --no-stream                        # 各容器占用
docker ps                                       # 谁活着，Up 多久（能看出谁重启过）
